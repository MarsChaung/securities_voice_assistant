# ADR-0012：混合式對話追問解析與核准段落選擇

- 狀態：內部語音測試受控啟用
- 日期：2026-08-11

## 背景

第一版自然對話使用固定文字規則判斷新問題、局部追問與換句話說，並以「到場」及
「時間」等規則擷取標準答案片段。這能穩定處理已知案例，但「銷戶三個月後能否再次
線上開戶」等省略主題或改用口語的追問，可能被當成新問題，再由一般檢索命中語意較
泛的知識。

## 決策

採用保守的混合式流程：

1. 明確的重述與局部追問仍走現有確定性快速路徑。
2. 規則判定為新問題、且同一 session 有成功知識回答時，才呼叫結構化對話語意模型。
3. 語意模型只輸出追問類型、參考輪次、完整檢索問句、局部焦點與信心分數；低信心、
   格式錯誤、逾時或不存在的參考輪次一律回退規則結果。
4. 檢索同時評估原始問句與上下文改寫問句。最近知識只有在改寫問句對該知識本身仍
   達到既有檢索門檻時才取得小幅加權，不會無條件沿用。
5. 自然回答模型收到編號後的核准答案段落，回傳回答及實際使用的段落編號。程式只接受
   存在的編號，並以選定原文執行數字、時間、禁語及個資輸出守門；生成遭拒時只回退
   選定的核准段落。

語意解析提供 `disabled`、`shadow`、`controlled` 三種模式，部署預設仍為 `disabled`。

## 安全與隱私邊界

- 當輪偵測到個資或機敏資料時，不呼叫對話語意模型。
- 語意解析只能影響追問關聯與檢索查詢，不能覆寫交易、帳務、投資建議、轉人工或其他
  既有政策結果。
- ContextStore 保留同一 session 最近八輪，個資輪次不會寫入；送入單次語意或回答模型時
  仍最多使用四輪。
- 送入語意模型的每輪問題、改寫查詢及回答皆設字數上限；判定為新問題後，不再把舊主題
  的歷史送入自然回答模型。
- 語意解析會保留最近同一知識主題的最早錨點與最近三輪，避免原始限制條件被連續細節追問
  擠出模型上下文。若模型仍判為新問題，原始問句會再與最近知識做一次受門檻限制的相關性
  比較；近期知識只有在分數足以與全域命中競爭時才可勝出，不會無條件黏住上一題。
- 段落選擇只能引用本輪命中的單筆有效發布知識，不得新增外部事實。
- 技術 log 只記模式、類型、信心及是否套用；development 專用 session 診斷才會依既有
  開關保存非敏感測試內容。

## 回退與評測

模型不可用、輸出格式錯誤、低信心或無效參考輪次時，維持原確定性解析。模型產生的
段落編號無效時，回退既有核准答案；答案未通過輸出守門時，回退模型已選定的核准段落。
合成多輪案例由 `evals/run_conversation_semantics.py` 評估分類、參考輪次、查詢改寫與延遲。
自然回答的新問題採語音優先的長度預算，原則上不超過 3 句或 160 個中文字；資格、限制、
例外與警語仍是不可省略資訊。稽核事件分開記錄語意、意圖、檢索及生成延遲，避免服務內部
計時掩蓋呼叫前的對話解析成本。

## 暫不納入

本階段不放寬 DomainPolicyEngine 的硬性拒答，不以大型 LLM 取代即時插話判斷，也不讓
LLM 自行判斷政策期限的數學或日期邊界。這些能力需各自建立安全評測後再分期處理。
