# ADR-0009：FAQ Excel 採預覽確認後建立草稿

- 狀態：已實作本機管理流程
- 日期：2026-07-23

## 決策

管理介面支援欄位為「項次／回答內容／問題1…問題N」的 `.xlsx`。上傳只建立預覽批次，
不立即修改知識庫；作者可檢查警示、取消選取不適合的項目，再確認建立草稿。

每一個 Excel 資料列轉為一項知識草稿，回答內容成為標準答案，非空且去除完全重複後的
問題成為 `retrieval` 問句變體。多項但彼此相關的回答不拆分，由後續人工編輯與審核判斷。

匯入者須選擇來源類型：

- `local_import`：供本機開發與授權測試資料使用，正式網址可留空，以匯入批次、檔案
  SHA-256、工作表及列號追溯。
- `approved_internal_faq`：代表已有正式資料集登錄頁，仍強制要求完整 HTTPS 網址。

系統保存：

- 原始檔名與 SHA-256。
- 資料集名稱、發布單位、來源類型、可選的正式網址與匯入者。
- 解析後的列、警示、錯誤與實際建立草稿的項目。
- 知識項目的批次、工作表、列號及原始項次定位。

原始 Excel 位元組不保存於資料庫、一般 log 或 Git。完全相同的檔案與來源識別會重用既有
批次，避免重複建立預覽。

## 預覽檢查

- 空白標準答案、超過 200 筆問句或疑似含個資／帳號／密碼／驗證碼：不可選取匯入。
- 缺少問句、缺少項次、跨知識重複問句及命中既有拒答／轉人工規則：顯示警示，由人判斷。
- 正規化後完全相同的標準答案若已存在於內部 FAQ 知識，該列標示既有知識編號並略過，
  不自動覆寫既有答案或建立第二筆知識。
- 所有成功匯入項目一律為 `draft`、`public_answer_allowed=false`，仍須逐項完成原有
  Maker–Checker 與發布流程才會進入 Runtime。
- 已發布 FAQ 的 `faq_general_guidance` 是安全可回答意圖的檢索相容標記；它不繞過
  個資與高風險政策、平台限制、最低相似度或歧義門檻。

## 未納入

本階段不自動判斷語意近似問句、不以 LLM 拆分或合併回答，也不自動核准或發布知識。
公司正式環境的 SSO、RBAC、惡意檔案掃描與保存期限仍須在移機前補齊。
