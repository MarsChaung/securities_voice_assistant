# ADR-0010：受治理的 ASR 領域詞彙與音近字回復

- 狀態：內部 Web Pilot 啟用
- 日期：2026-07-26

## 背景

即時 ASR 可能將證券專有名詞轉成同音或近音字。例如「假除權息」被辨識為「甲竹全席」
或「甲雛全息」時，原始政策仍會將問題判斷為一般證券知識，但一般混合檢索分數分別只有
`0.2120` 與 `0.2383`，低於 `0.4` 門檻。直接降低門檻會在知識量增加後提高錯答風險。

## 決策

採用兩層受控處理：

1. `/v1/voice/config` 只從當下符合發布、來源、效期與複審資格的知識，取標題及產品名稱
   產生精簡 ASR context。瀏覽器在建立 MLX Audio 即時 WebSocket 時送出 context；
   Whisper 使用 `initial_prompt`，支援的其他模型使用 `system_prompt` 或 `context`。
2. 若原始問題已通過個資、確定性政策及 LLM Intent Router，但語音通道的一般證券知識
   仍無法命中知識，才使用不含聲調的中文拼音比對已發布知識標題與正式問句變體。

音近候選最低分數為 `0.9`，第一、第二名差距須至少 `0.08`。唯一高信心候選以
`ASR-PHONETIC-001` 回答原核准標準答案；多個高信心候選以 `ASR-PHONETIC-002` 要求
使用者重述。短於三個中文字、超過二十四字、低信心及無候選情況維持 `KNO-001`。

## 安全邊界

- 音近回復只適用 `voice`，文字輸入不自動改字。
- 敏感資料、硬性拒答、轉人工或 LLM 風險結果會在音近回復前結束流程，不能被覆寫。
- 第一版只開放 `general_securities_knowledge`，不套用交易、帳務、憑證或身分流程。
- 候選只來自 Runtime 當下可回答的知識，不使用模型自身知識，也不產生新的標準答案。
- 稽核仍不保存音訊、逐字稿或修正文字；以規則 ID、答案 ID、分數與既有安全中繼資料
  判斷是否套用音近回復。

## 限制與後續

拼音近似不能完整處理多音字、語流變音、台灣國語及所有環境噪音。正式上線前須用取得
授權且完成去識別的實際音訊評估專有名詞正確率、錯誤修正率、歧義率與安全繞過率。
知識量接近完整 FAQ 規模後，應在治理 UI 增加獨立的 ASR 詞彙欄位，避免將全部標題塞入
模型 context，並重新校準 context 長度、音近分數及歧義門檻。
